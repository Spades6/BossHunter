# 三分钟演示脚本

## 0:00–0:25｜先讲判断

“很多求职工具默认把目标设成投得更多。BossHunter 的判断相反：AI 可以帮人看更多岗位、整理更多信息，但最终投递决定不应该交给机器。”

指向首屏三条边界：匿名数据、不调用真实招聘平台、不会发送消息。

## 0:25–1:15｜岗位不是只看关键词

点击“开始 3 分钟演示”。

“这里有一份匿名简历和 6 条模拟 JD。系统先用薪资、城市和一票否决条件预筛，再结合完整 JD 与简历做深度评分。不是每个岗位都给高分。”

操作：

1. 点击第 1 个岗位，展示 92 的预筛分和 93 的深度评分。
2. 指出“为什么是这个分数”和“需要人判断的风险”。
3. 展开被过滤岗位，展示高频出差命中一票否决，以及 Java 技术栈不匹配。

## 1:15–1:55｜AI 给建议，人做决定

“排序之后没有自动投递。用户能改选，也能看每条个性化招呼语。”

保留默认两个岗位，点击“人工确认并继续”。

“漏斗里人工确认是 2，真实发送仍然是 0。真实本地模式还会受时间窗、每日上限和随机间隔约束。”

## 1:55–2:40｜跟进不是聊天记录堆积

点击“模拟收到 HR 消息”。

“当 HR 说‘发份简历’，系统把消息识别成一个待处理任务，提取岗位重点，用原始简历做重排和改写。它不发明经历，也不自动发附件。”

指向：

- 识别意图、提取重点、生成草稿、等待确认四步。
- “事实边界已检查”。
- “不自动发送”。

## 2:40–3:00｜收尾

“公网评委模式只展示安全、可复现的闭环。真实产品是 Python、React、SQLite 和本地 Browser Runtime 组成的长任务系统，处理采集、AI 服务、浏览器中断、停止恢复和人工确认。BossHunter 不是帮人无脑海投，而是把有限注意力留给真正值得判断的机会。”

## 可能追问

### 演示里真的调用模型吗？

没有。为了不要求评委提供 API Key，也避免模型临时波动，公网沙盒使用固定可复现结果。真实本地版本通过 Anthropic 或 OpenAI 兼容协议调用用户选择的模型。

### 为什么不把真实自动化部署到云上？

真实流程依赖用户本地已登录的 Chrome 和个人简历。把账号会话与简历集中传到云端会破坏原本的隐私定位，也让评委承担不必要风险。

### 会不会自动海投？

不会。发送前必须人工确认，产品还提供时间窗、每日上限、随机间隔和停止机制。第三方平台自动化仍可能违反其规则，项目明确提示风险。
